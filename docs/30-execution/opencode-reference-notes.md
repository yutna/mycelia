# OpenCode reference notes

Status: Non-normative reference

Source: `anomalyco/opencode`, branch `dev`, `services/site/src/docs/content/` (English pages; `v1/` and
translations excluded), release notes v2.2.6 to v2.4.2, and `packages/protocol/openapi.json`. Read on
2026-11-27.

This document is not part of the specification. It records what the OpenCode V2 documentation says, as input for
the [OpenCode runtime contract](opencode-runtime-contract.md) and the reference runtime. It uses no RFC 2119
language and creates no requirement. Where it conflicts with a normative document, the normative document wins.

Caveats:

- The `dev` branch may be newer than a released version. Verify a behavior on the pinned OpenCode version before a
  requirement depends on it.
- The notes are terse working notes, grouped by docs page. "Mycelia relevance" lines are design input, not
  decisions.
- Credentials, auth stores, and the OpenCode database are described only by location and purpose. Never read them as
  evidence.

## Key findings

1. Config merge order: settings low -> high = global, direct `opencode.json(c)` far -> near, `.opencode/` far ->
   near, system `/etc/opencode`, managed. Every `.opencode` file beats every direct file. Policies reverse:
   managed > system > Console > global > direct (outer beats inner) > `.opencode` (outer beats inner). (config,
   policies)
2. Permissions vs policies: permissions = per-agent ordered allow/deny/ask, base is allow-all, last match wins,
   `ask` blocks headless. Policies = binary hard-deny after permissions and saved approvals, broader config wins,
   repo cannot loosen. `--auto` approves everything not denied. (permissions, policies, cli/commands)
3. Guard hooks: V2 plugin `ctx.tool.hook("execute.before")` can throw to block / rewrite input;
   `ctx.permission.hook("evaluate")` can tighten allow/ask (config deny is final); `context`, `retry` hooks;
   `session.interrupt`, `permission.reply`. Events are live-only (subscribe before prompt, persist yourself);
   `opencode session export`. Open: whether MCP/shell pass through execute.before; plugin load failure mode.
   (build/plugins/server, build/client)
4. Jev: endpoint `/inference/systemone/v1/systemone` (Go: `/inference/go/systemone/v1/systemone`); request
   `{model, state, questions:{id:{type, instructions, criteria}}}`; response schema only at docs.typesafe.ai.
   `jev-1.13-free` is listed only in the pay-as-you-go table; Go-key support and free-tier retention/training
   terms are NOT documented -> must be tested. (console/models, console/api/inference)
5. Using the Go credential without exposure: no documented way for a plugin/script to reuse OpenCode's stored
   credential. Documented routes: env var or `{env:}`/`{file:}` in config, `opencode service set env` (stores in
   `~/.config/opencode/service.json`). Saved accounts live in the SQLite DB (never capture). Go usage is visible
   without the key via server `usage.limits` and `GET /inference/go/v1/usage` (needs key). Proposal: a separate
   Console API key in a file readable only by the runtime user, referenced by path. (config, cli/*, console/go)
6. Claude Agent provider: added v2.2.3 (guided setup v2.2.4) -> works on 2.2.6; v2.4.0 adds `configDir` (list =
   account failover), claude-agent web search, process-leak and rename fixes. Claude heads need >= 2.4.0 for account
   failover. Plugin `http.request/response` hooks do not run for it. (claude-agent, releases)
7. Stack ADR input: plugins, SDK (`@opencode/sdk`, in-process) and client (`@opencode/client`) are TypeScript
   (Effect variants exist) -> TypeScript is the native choice.
8. Requirement -> native vs wrapper map (vs SPEC.md section 10, docs/30-execution/opencode-runtime-contract.md,
   issue #99 A-F). The contract's capability matrix holds; corrections and additions from the docs:

   | Need | Native in OpenCode | Wrapper Mycelia must provide |
   | --- | --- | --- |
   | Policy red lines (CORE-003) | `policies` hard-deny, `Blocked by configuration policy` | Put them in global or `/etc/opencode` scope (a repo cannot loosen); lint, because invalid statements are dropped with only a log warning; canaries asserting exact denial counts (#99 D) |

warning.

## Notes by page

### config.mdx

- Files: JSON or JSONC, `$schema: https://opencode.ai/config.json` (schema = source of truth for fields).
- Locations: system `/etc/opencode/` (also loads `agents/ commands/ skills/ plugins/` for all users); macOS MDM
  plist; global `~/.config/opencode/opencode.json(c)`; project `opencode.json(c)` and `.opencode/opencode.json(c)`.
- **Merge order (settings, low -> high)**: global -> direct `opencode.json(c)` files from farthest dir to closest ->
  `.opencode/opencode.json(c)` files farthest to closest -> system `/etc/opencode` -> managed prefs. So EVERY
  `.opencode` config overrides EVERY direct config. Non-conflicting settings are kept. Docs advise one form per tree.
- **Policies evaluate in reverse** (broader wins): see policies.mdx precedence table.
- Top-level keys seen: `shell`, `model` (`provider/model`; root default drops `#variant`), `default_agent`,
  `update` (`disable|notify|auto`, global only; auto does not restart a running server), `username`,
  `permissions` (array), `policies` (array), `agents` (map), `snapshots` (bool), `watcher.ignore`, `formatter`,
  `media.image.*`, `tool_output.{max_lines:2000,max_bytes:51200}`, `websearch.provider`, `mcp.{timeout,servers}`,
  `compaction.{auto,keep.tokens,buffer}`, `warming`, `skills` (dirs/URLs), `commands` (map with `template`),
  `instructions` (files/globs/URLs, loaded with AGENTS.md), `references` (named dirs or git repos),
  `worktree.directory` (parent for new worktrees; default server data dir `worktree/<6-char project id>`;
  plugins can register a worktree strategy), `plugins` (string or `{package, options}`), `providers`
  (models, `settings.apiKey`, `settings.baseURL`, `settings.transport: "websocket"`, `settings.compaction.type`).
- Variables: `{env:NAME}` (unset -> empty string), `{file:path}` (relative to config dir, absolute or `~/`;
  missing -> empty string). Silent empty substitution is a guard risk: validate required env before runs.
- Experimental (`experimental.*`, unstable): `todo` (todowrite tool), `subagent_depth` (default 1 = subagent
  cannot spawn subagent), `image_generate`, `location_idle_timeout` (default 60 min), deprecated `policies`.
- Mycelia: Mycelia's `opencode.json` at repo root is overridden by any `.opencode/opencode.jsonc` — pick ONE form
  for the factory profile; put hard limits in policies at global/system level so a repo cannot loosen them.

### permissions.mdx

- Rule = `{action, resource, effect: allow|deny|ask}`; ordered; **last match wins**; no match -> `ask`.
  V2 names: `permissions`, `shell`, `subagent` (V1: `permission`, `bash`, `task`).
- Wildcards: `*` (incl. `/`), `?`; whole-value match; shell pattern ending `*` also matches bare command.
- Rule assembly: lower-priority config first, then global, then agent rules appended (agent rules extend, not
  replace). A custom subagent uses its own permissions, NOT a subset of its parent's.
- Multi-resource ops: any deny -> deny; else any ask -> ask; else allow.
- Actions: `read, edit (edit/write/patch), glob, grep, shell, subagent, skill, question, webfetch, websearch,
  generate_image, external_directory, <server>_<tool> (MCP), opencode_list_mcp_resources,
  opencode_read_mcp_resource, execute (Code Mode)`; plugins may define more. `doom_loop`, `lsp` are not V2 actions.
- **Default base policy for every agent: `* * allow`** plus ask on `*.env`/`*.env.*` reads. `external_directory` is
  allowed by default -> outside-project reads/edits proceed silently unless a rule is added.
- Shipped agents: build (questions allowed), plan (deny edits except `~/.opencode/plan`), general (deny questions,
  subagents), explore (read-only + shell + web), title/summary (deny all), compaction (base).
- Shell scanner: bash/zsh/sh/PowerShell; extracts subcommands and `cd` targets; unanalysable commands (`eval`,
  malformed) FAIL with a scanner error if any shell deny rule applies; otherwise need whole-command +
  `external_directory *` approval. Docs: prefer a narrow allowlist, directory inference is best effort; shell has
  full host-user authority.
- Approvals for `ask`: `once`, `always` (saves project-scoped allow pattern, never overrides a configured deny),
  `reject` (rejects all pending in session, optional feedback). **Non-interactive clients must decide how to answer
  asks** -> headless factory must have zero `ask` paths or an automated responder.
- Mycelia: start from `* * deny` explicitly (base is allow-all), allowlist per role; add
  `external_directory * deny`; treat saved "always" approvals as drift (audit them).

### policies.mdx

- Separate from permissions: binary (`allow|deny`), never prompt, only tighten. Statement `{action, resource,
  effect}`; actions: `provider.use, tool.use, integration.connect, integration.use, mcp.use, skill.use,
  plugin.use, websearch.use`. Invalid statements are dropped with a warning in the server log (check the log!).
- Last match wins, no specificity; nothing matches -> allowed.
- `tool.use` resource `<action>:<value>` (e.g. `shell:git push *`, `edit:*.env`, `read:*/.ssh/*`,
  `external_directory:*`, `subagent:general`, MCP tool name, `*`). Applied AFTER agent rules and saved approvals ->
  error `Blocked by configuration policy`. `allow` never grants; it only lifts an earlier broader deny.
- `provider.use` removes a provider from catalog even with credentials (e.g. deny `*`, allow `opencode-go`).
- `integration.use` resource `<integration>#<account>`; free tier signed-out = `opencode`.
- `mcp.use`/`skill.use`/`plugin.use` remove/unload by name (>= 2.2.3); `websearch.use` (>= 2.2.6).
- **Precedence (highest first)**: macOS managed prefs; system `/etc/opencode`; connected Console workspace (fetched
  ~1/min; last statements kept if unreachable); global `~/.config/opencode`; direct `opencode.json(c)` (outer beats
  inner); `.opencode/opencode.json(c)` (outer beats inner). A repo cannot re-enable a globally denied item.
- Policies do NOT sandbox plugin code.
- Mycelia: hard guards = policies in global/system scope (`provider.use` allow only `opencode-go` [+ jev path],
  `tool.use` deny `shell:git push *`, `shell:sudo *`, `read:*auth.json`, etc.); permissions = per-role allowlists.
  Canary test: each deny must produce `Blocked by configuration policy`.

### plugins.mdx

- `plugins` entries: npm name, `name@ver`, scoped, local dir (relative to the config file; must be a directory,
  a single file is skipped), `file://`, or `{package, options}`. Arrays from all config files are applied low ->
  high (they accumulate, not replace).
- Auto-discovery: direct `.ts`/`.js` files and package dirs in every discovered `.opencode/plugins/` and
  `~/.config/opencode/plugins/`. A `plugins/` beside a root `opencode.json` is NOT auto-discovered.
- Control: entries in order; `-id` disables, `*` all, `prefix.*` wildcard, later id re-enables.
  `opencode.config.policy` and `opencode.provider.opencode` ignore removals (a repo cannot turn off policy).
- CLI: `opencode plugin add|list [--builtin]|check|update|remove` (global package plugins).
- **Pinning**: exact versions and full commit hashes are pinned. Ranges, `@latest`, git branches auto-update on
  startup and every 24 h and reload. Bare name / git repo stays on the installed version, but `plugin update`
  moves it. Mycelia: pin exact version or commit hash (matches AGENTS.md "pin plugins").
- Reload: watched config dirs reload automatically; else `opencode service restart`.
- GUI plugins export `./gui-experimental`; TUI-only plugins go in `cli.json`.

### agents.mdx

- Markdown agents: `~/.config/opencode/agents/<name>.md`, `.opencode/agents/<name>.md` (nested path -> id
  `team/reviewer`); frontmatter = same fields as `agents.<id>` config; body = `system` prompt.
- Fields: `description`, `mode` (`primary` default | `subagent` | `all`), `model` (`provider/model#variant` or
  `{providerID, model, variant}`), `system` (replaces the provider base prompt; instructions/skills/references
  still added), `permissions` (appended after global rules), `steps` (max model steps; on the last step tools are
  removed and the model must summarize; new user input resets), `hidden` (visibility only, NOT security),
  `color`, `disabled`, `request.{headers,body}` (stored but NOT yet sent by the V2 runner).
- Default agent: must exist/visible/primary-capable, else `build`. Session stores its agent and model separately.
- Subagents: fresh context in child sessions, always background; parent gets a report when the child is idle.
  Parent's `subagent` permission decides who it may launch; the child uses its own permissions. Subagent model:
  its own, else the parent's.
- Merging: later scalars replace, request maps merge, permission rules append.
- Legacy fields (`temperature`, `tools`, `maxSteps`, `permission`, ...) must not be used in V2.
- Mycelia: one agent file per role (implementer, reviewer, ...) with explicit `* * deny` first, then allowlist;
  `steps` = budget guard; model pinned per role (`opencode-go/deepseek-v4.1-flash`).

### snapshots.mdx

- `/undo` / `/redo` / Revert stage a rollback of conversation + files; snapshots taken before each model step and
  at step end; the assistant message records changed paths (useful evidence: per-step changed-file list).
- Scope: session active directory inside a git worktree; tracked + non-ignored untracked files <= 2 MiB; not ignored
  files, not outside dir, not git metadata/side effects. Needs git.
- Stored in a separate internal git object DB in the OpenCode data dir (sensitive; full file contents). Not a
  backup/transaction; shell side effects are not reversed. `snapshots: false` stops capture.
- Mycelia: not an evidence store; evidence must come from git commits/diffs + event logs. Data dir is sensitive.

### compaction.mdx

- Auto compaction near the context limit: summary of the whole conversation + recent ~15k tokens kept.
  Settings: `compaction.auto` (true), `background` (true; pre-writes summary, held in memory, costs tokens even if
  unused), `keep.tokens` (15000), `buffer` ("15%", at least 16k; % of window kept free, or a token count).
- Manual: `opencode api post /api/session/<id>/compact --data '{"id":"..."}'` (idempotent with `id`; async;
  follow `session.compaction.*` events). `opencode api` discovers and authenticates with the background service.
- `agents.compaction.model` picks the summary model (fallback session model). Native provider compaction
  (`settings.compaction.type: native`, OpenAI Responses only) gives opaque encrypted checkpoints.
- Summary structure: objective, requirements, decisions, completed/active work, blockers, next moves, files.
  After compaction current instruction files become the baseline. Earlier messages stay stored.
- Too-long request: compact and retry once, second rejection = error.
- Mycelia: compaction is lossy -> acceptance criteria and evidence must live in files/issues, not only in the
  session; consider a small work-item scope per session so compaction is rare.

### index.mdx

- Purpose: install + connect. OpenCode = open-source coding agent (TUI, desktop, web, Docker).
- Capabilities: install via `curl -fsSL https://opencode.ai/v2/install | bash`, `brew install
  anomalyco/tap/opencode-v2`, `npm i -g @opencode/cli`, bun/pnpm/yarn/vite+, aur `opencode-beta`, `mise use -g opencode`
  (needs mise >= 2026.10.9, older installs OpenCode 1). npm uses postinstall to pick native binary (bun needs `--trust`,
  pnpm `--allow-build=@opencode/cli`). Standalone tar.gz/zip per platform incl. linux glibc/musl, x64 baseline. No
  Windows pkg managers. Web via `opencode pair` (one-time link, expires 5 min, 127.0.0.1). Docker:
  `ghcr.io/anomalyco/opencode:<version>` (versioned tags, e.g. 2.0.0). Connect providers with `/connect`; OpenCode Go =
  $10/month sub.
- Headless/CI: install via standalone binary or pinned docker tag; pin version.
- Version: V2 installer path `/v2/install`; V1 and V2 share `opencode` command, not side by side.
- Mycelia relevance: pin install (mise/docker tag) and record version in PR (AGENTS.md requires >= 2.2.6). Native.

### tools.mdx

- Purpose: built-in tool catalog.
- Capabilities / limits: `read` (path, offset, limit; 2000 lines & 50 KiB/page; lines cut at 2000 chars;
  PNG/JPEG/GIF/WebP/PDF up to 20 MiB passed to model; perm `read`, resource normalized path). `glob` (pattern, path,
  hidden, limit; default 100, 30s timeout; perm `glob`, resource pattern). `grep` (pattern, literal, path, include,
  caseSensitive, limit; default 100 lines, 30s; perm `grep`, resource = pattern not path). `edit` (path, oldString,
  newString, replaceAll; must match once; may run formatter; perm `edit`, resource path). `write` (path, content;
  creates parent dirs; perm `edit`). `patch` (patchText with `*** Add File/Update File/Delete File`; only exposed for
  supported GPT models, other models get edit+write; perm `edit` w/ every path). `shell` (workdir, timeout ms, default 2
  min foreground, `background` true => no timeout, notifies session; big output truncated and kept in managed file; perm
  `shell` with each scanner-produced command as resource; scanner also checks external workdir and inferred dirs).
  `webfetch` (url, format markdown|text|html, timeout <=120s; textual only; perm `webfetch`, resource URL). `websearch`
  (query; perm `websearch`). `generate_image` (experimental; perm `generate_image` resource model;
  `experimental.image_generate`). `question` (perm `question` resource `*`; needs interactive client; dismiss cancels).
  `skill` (perm `skill`, resource ID). `subagent` (agent id, description, prompt; ALWAYS background; returns sessionID,
  parent gets `<subagent>` message on idle; only mode=subagent agents; default nesting depth 1; perm `subagent` resource
  agent ID). `execute` = Code Mode JS runtime (no fs, imports, timers; has `fetch`; calls catalog tools; deny `execute`
  resource `*` removes Code Mode and MCP tools become direct tools, each with full definition per request; nested tools
  still enforce own perms). `opencode.session` namespace: rename, move (`opencode_session_rename/move` without Code
  Mode). Worktrees: `worktree_create/list/remove` (remove uses `edit` perm on dir; others no perm). `browser` Code Mode
  namespace for desktop app (deny `browser` resource `*` removes it; no per-op prompts; 5 MiB file transfers).
- Precedence/merge: paths outside active Location/project worktree also checked against `external_directory`, ALLOWED BY
  DEFAULT.
- Security: shell has host user's full fs/process/network authority; use narrow `shell` rules. Page content from browser
  is untrusted. MCP tool perm action = `<server>_<tool>`, resource `*`. Code Mode `fetch` is a network path to consider
  (webfetch deny may not cover `execute` fetch; verify).
- Headless: `question` tool needs interactive client; deny it (or `permissions` question deny) in CI to avoid hangs.
  `subagent` background semantics.
- Mycelia relevance: action names to deny in `permissions`: shell (patterns like `git push *`), edit, webfetch,
  websearch, external_directory, subagent, execute, browser, generate_image, question. Evidence capture of tool calls
  not native here (need plugin hooks / API events). Weak implementer model: consider denying `execute`, `browser`,
  `generate_image`, `websearch` to shrink attack surface and context.

### instructions.mdx

- Purpose: AGENTS.md loading.
- Capabilities: global `~/.config/opencode/AGENTS.md` + every AGENTS.md from workspace dir up toward home (stops at
  project root if outside home). Combined order: global, then nearest->farthest. No conflict resolution (just
  concatenated). Nested AGENTS.md below workspace load on read of a file/dir under them (nearest-first, deduped while in
  history; re-inject after compaction/revert; edits to nested file NOT detected after load). Global/upward files
  hot-reload: change injected as "instruction update" before next request; removing all notifies. Values privileged
  (clients see which sources changed, not contents).
- Config: `instructions: ["CONTRIBUTING.md","docs/guidelines/*.md","~/rules/x.md","https://..."]` (relative: searched
  each dir workspace->project root; `~/`; absolute/glob; http(s) fetched at config load, 5s timeout; missing skipped;
  combined across config docs; loaded AFTER AGENTS.md in list order).
- Prompt assembly order: 1 agent/provider system prompt, 2 Code Mode guidance, 3 MCP/reference/skill guidance, 4
  AGENTS.md then configured instructions, 5 built-in date+env, 6 session-specific instruction entries via API.
- CLAUDE.md fallback: directory without AGENTS.md reads CLAUDE.md; no global AGENTS.md => `~/.claude/CLAUDE.md` read.
  AGENTS.md wins per directory. Env: `OPENCODE_DISABLE_CLAUDE_CODE_PROMPT=1` skips all CLAUDE.md;
  `OPENCODE_DISABLE_CLAUDE_CODE=1` also skips `.claude` skills; `OPENCODE_DISABLE_PROJECT_CONFIG=1` skips project
  AGENTS.md discovery (relative `instructions` then resolve vs global config dir). Server reads env at start; background
  service: `opencode service set env NAME VAL` + `opencode service restart`.
- Mycelia relevance: HOST HAZARD: on a host with Claude Code, `~/.claude/CLAUDE.md` is read as
  fallback if `~/.config/opencode/AGENTS.md` is absent, leaking personal rules into the factory; set
  `OPENCODE_DISABLE_CLAUDE_CODE=1` (or create an empty/explicit global AGENTS.md) in CI/systemd. Repo already says no
  CLAUDE.md (AGENTS.md only) - consistent. Native; instruction URLs fetched at load = untrusted-network input, avoid in
  CI.

### skills.mdx

- Purpose: SKILL.md reusable instructions, loaded on demand via `skill` tool.
- Discovery: global `~/.config/opencode/skills`, `~/.claude/skills`, `~/.agents/skills`; project `.opencode/skills`,
  `.claude/skills`, `.agents/skills` (walk cwd up to project root). `skills/review.md` (root-level md) or any nested
  `SKILL.md` (depth <= 6; hidden dirs and node_modules skipped; dir with SKILL.md is leaf). Extra sources: `skills:
  ["./team-skills","~/x","/abs","https://.../"]` (relative from OpenCode working dir NOT config file; arrays combined).
  HTTP catalog: base URL + `index.json` `{skills:[{name,version,files:[...]}]}`; files fetched from
  `<base>/<name>/<file>`; must be safe relative same-origin; bump `version` to refresh cache.
- Frontmatter (all optional): `name` (display only), `description` (required to be advertised),

### warming.mdx

  `headers`->`ANTHROPIC_CUSTOM_HEADERS`; `body`->`CLAUDE_CODE_EXTRA_BODY`; per-model overrides allowed. Config overrides
  shell vars. Second account: separate `CLAUDE_CONFIG_DIR` (`settings.configDir: "~/.claude-2"` on a model such as
  `sonnet-2` with `modelID:"sonnet"`). Rotation: `settings.configDir: ["~/.claude","~/.claude-1"]` moves to next account
  on usage limit; only for subscription logins (not apiKey/authToken); chat sticks to the account that last answered.
- Cost shown: subscription none; API key/Bedrock/Vertex/Foundry priced per provider; custom base URL none.
- Web search: `websearch.provider: "claude-agent"`.
- Limitations: Claude Code must be on same machine as server (no remote workspaces); Claude Code system prompt REPLACES
  OpenCode's built-in prompt (custom agent prompts still apply); no temperature/top_p/top_k/seed/stop; plugin
  `http.request`/`http.response` hooks do NOT run (Claude Code makes API calls) - hurts request-level evidence capture;
  no `/usage`, `/loop`, auto mode, agent teams. Errors: `Claude Code is not installed`, `Claude Code is not logged in`,
  `Claude Code ... is too old` (`claude update`).
- Security/host-specific: needs a logged-in Claude Code. On a host with more than one Claude Code profile, pin
  `settings.configDir` to the profile (or a dedicated login) meant for the factory, and check that `CLAUDE_CONFIG_DIR`
  in the service env does not point at a profile with other obligations (for example organization telemetry). Claude
  Code's own hooks/CLAUDE.md are not loaded, so
  user CLAUDE.md rules do not apply; OpenCode permissions govern tools. Credential storage is Claude Code's own (do not
  read).
- Headless: works if `claude` is on PATH for the systemd service and already logged in (interactive login once);
  `service set env OPENCODE_CLAUDE_PATH`. Subscription usage limits (5h/weekly) apply; rotation can spread.
- Mycelia relevance: native route for "later Claude"; but loses plugin http hooks and sampling controls, replaces system
  prompt, and routes tool calls via OpenCode permissions (guards still apply). Page is marked noindex (possibly
  unstable/experimental) - verify before depending on it.

### cli/acp.mdx

- Purpose: `opencode acp` runs OpenCode as an Agent Client Protocol agent (Zed etc.), NDJSON JSON-RPC over stdio, ACP
  protocol v1. Spawns its OWN private server (not the shared service), opens no network port, exits when stdin closes.
- Auth: uses existing credentials (`opencode auth login` first). One method `opencode-login`; `authenticate` collects
  no credentials; prompt failure -> ACP `auth_required`. `opencode acp --login` runs login flow then exits (0 = ok).
  Stdout carries only ACP messages; `opencode --print-logs acp` sends logs to stderr.
- Capabilities advertised: loadSession, mcp http (no sse), prompt image+embeddedContext, session
  additionalDirectories/close/delete/fork/list/resume.
- Sessions: `cwd` must be absolute; load/resume/fork need the session's dir (or same project); `session/list` max 100
  per page, subagent sessions carry `_meta["opencode/child-session"]` {id,parentID,depth,title}; one prompt at a time
  per
  session (second `session/prompt` errors); `session/cancel` or `$/cancel_request` -> `stopReason:"cancelled"`, rejects
  pending permission requests, unfinished tool calls reported `failed`; `session/close` interrupts + detaches (session
  kept); `session/delete` cancels then removes. Prompt failure error `data` has `errorName`, `status`, `retryAfterMs`.
- Config options on new/load/resume/fork: `model` (provider/model[/variant]), `effort`, `mode` (primary agents);
  `session/set_config_option`, `session/set_mode`.
- Permissions: options `once`(allow_once) / `always`(allow_always) / `reject`(reject_once); file changes include `diff`.
  Additional dirs grant external-directory access but read/edit/shell rules still apply; stored on the session.
- Questions: `elicitation/create` form mode only if client advertises `elicitation.form`; never sends forms that may
  collect secrets; else question is cancelled and model told to continue without an answer.
- Observability extras: `usage` on prompt response (inputTokens/outputTokens/totalTokens, excludes child sessions),
  `usage_update` (used,size,cost USD incl. children), `_meta["opencode/retry"]` {attempt,nextRetryAt,error{type,
  message,status}} on `session_info_update`, `_meta["opencode/compaction"]` {status started|completed|failed,
  messageId, reason auto|manual}, compaction RFD updates, child session updates with `<childSessionId>:` tool call id
  prefix. MCP servers passed by client (stdio/http) added per directory for life of process; `integration.use` policies
  still apply. Slash handling: `/compact`, commands, skills.
- Mycelia relevance: ACP is an alternative control surface to HTTP SDK but heavier; NOT needed. Useful only as a model
  of what OpenCode itself treats as the canonical event set (retry, compaction, usage/cost, child sessions). Native
  usage/cost reporting means cost budget evidence can come from `usage_update`/session export.

### build/client/index.mdx

- Purpose: `@opencode/client` Promise client for the HTTP API (generated from the same contract as `/api`).
- API: `OpenCode.make({baseUrl, headers?, fetch?})`; groups: `client.session.create({location:{directory}})`,
  `client.session.prompt({sessionID,text})`, `client.session.list(undefined,{signal})`, `client.server.info()`,
  `client.event.subscribe({types?})`, `client.rpc(Def)`. Every op takes trailing request options `{signal, headers}`.
  Auth: pass `headers` (Basic `opencode:<password>`; docs example shows Bearer for a fronting proxy).
- Events: `for await (const e of client.event.subscribe({types:[..]}))`; one lazy shared SSE-like connection per client;
  LIVE ONLY: no replay, no auto-reconnect; source failure ends all subscriptions (re-subscribe after recovery); late
  subscriber gets the current `server.connected` marker (always delivered even with `types` filter - use it to
  resync); filtering is client-side on the shared connection; shared source waits for subscribers to accept each event
  so buffer before slow work. Evidence implication: wrapper must persist events itself and handle reconnect + resync by
  reading session state/messages after `server.connected`.
- Plugin RPC: `client.rpc(Def).method(input,{location,signal,headers})`, `.events.on(name,cb)` /
  `.events.subscribe(name)`; HTTP: `POST /api/rpc/{rpcID}/{method}` `{ "input": ... }` -> `{ "output": ... }`.
  Declared errors reject; reserved `rpc.*` are framework failures.
- Local service (Node): `import {Service} from "@opencode/client/service"`: `discover()`, `ensure({file,version,
  command,onStart})`, `stop()`, `headers(endpoint)`; default command `opencode serve --service`; registration file path
  customizable (e.g. `/var/run/opencode/service.json`); `version` can be exact or predicate (`v => v.startsWith("2.")`).
- NOT documented on this page: abort/interrupt, permission reply, message listing methods by name (see plugin ctx:
  `session.interrupt({sessionID,resume})`, `session.wait`, `session.context`, `permission.{list,get,reply}`; the client
  is "essentially" the same surface, so expect `client.session.interrupt`, `client.permission.reply`).
- Mycelia relevance: primary control path for `opencode serve` mode. Native.

### build/plugins/server.mdx

- Purpose: server plugin API (V2). Plugin = `Plugin.define({id, setup(ctx)})`; `setup` may return cleanup fn.
- Context `ctx` = server client + plugin-only APIs: `ctx.app.version`, `ctx.location` {directory, workspaceID?,
  project{id,directory,canonical}}, `ctx.options`, `ctx.storage.{get,set,remove,scan({prefix,after,limit})}` (durable
  JSON
  per plugin id), domains: `agent, aisdk, command, event, experimental.{terminal.read,generate}, integration, mcp,
  model,
  permission, plugin.list, provider, reference, rpc, session, shell, skill, storage, tool, vcs, websearch, worktree`,
  `credential.activate`.
- Two mechanisms: TRANSFORMS (sync, replayable edits of domain state; `ctx.<domain>.transform(editor=>...)` returns
  `Registration{dispose()}`; `reload()` re-applies after captured external inputs change; callbacks must be cheap, pure,
  repeatable; applied in registration order) and HOOKS (intercept live operations; `ctx.<domain>.hook(name, cb, opts?)`;
  multiple plugins run in plugin order, later see earlier changes).
- TRANSFORM domains: agent (`list/get/default/update/remove`), provider (`add/update/remove`,
  `models.set/update/remove`),
  model (`list/get/update/remove`, `default.get/set`; can set `enabled`, `limit.context`; policy by cost), command
  (`add({name,description,execute({sessionID,prompt,delivery})})`), integration (auth methods api-key/oauth/command),
  mcp (`set/update/remove/get/list`, `disabled:true` disconnects), reference (local|git), skill (`add/update/remove`,
  `autoinvoke`), tool (`namespace/add/update/remove/get/list`), vcs (providers, `default.set`), worktree (strategy
  `{id,create,remove,list}`; `Worktree.OperationError({message,forceRequired})`), websearch (`default.set(id|false)`
  disables websearch).
- TOOLS: `ctx.tool.transform(editor => editor.add({name,description,input:JSONSchema,options:{namespace,codemode},
  execute(input,context)}))`; context has `sessionID, agent, messageID, id, signal, progress()`; returns
  `{content}`; name `ns_name` (dots/unsupported chars -> `_`); later registration overrides same effective name;
  `update`/`remove` also work on BUILT-IN/MCP tools by effective name (e.g. `editor.remove("bash")` presumably; docs
  show
  `update("acme_greeting")`, `remove("acme_obsolete")`; replays after MCP catalog refresh). Each model request captures
  a
  stable tool snapshot (changes affect future requests only). `freeform` input (text|regex|lark) if model supports.
- PERMISSIONS API: `ctx.permission.assert({sessionID, agent, source:{type:"tool",messageID,id}, action, resources[],
  save[], metadata})` evaluates session rules incl saved approvals, prompts on `ask`, rejects with `Tool.Error` on deny
  (model sees reason) or ends step on plain rejection. Any `deny` blocks; otherwise any `ask` prompts.
  `ctx.permission.list({sessionID})`, `.get({sessionID,requestID})`, `.reply({sessionID,requestID,decision:"once"|...})`
  (other decision values not listed here; ACP shows once/always/reject). `ctx.session.update({sessionID, permissions:
  [{action,resource,effect:"deny"|...}]})` REPLACES session-scoped rules; evaluated after the agent's rules, LAST MATCH
  WINS; child sessions inherit rules in effect at creation (so a later rule can override an agent deny? ordering means
  session rules can override agent rules; guard must account for that).
- SESSIONS API: `create({title})`, `get`, `list({directory,limit,cursor})`, `context({sessionID})` (messages), `prompt({
  sessionID,text,files,agents,skills,delivery})` -> inbox item, `generate({sessionID,prompt})` -> `{text, tokens,
  cost}`,
  `command({sessionID,name,text})`, `synthetic({sessionID,text,resume})`, `compact`, `interrupt({sessionID,resume})` ->
  `{interrupted}` (this is ABORT), `wait({sessionID})`, `remove` (stops execution, deletes children), `update({title,
  permissions})`, `move`, `switchAgent`, `switchModel`, `instructions.entry.{put,list,remove}({sessionID,key,value})`
  (keyed `<context key="...">` blocks in instructions; announced at next step boundary). `experimental.generate.{text,
  image,decisions}` call a model without session/tools (use for LLM-judge in guards).
- EVENTS: `ctx.event.subscribe({types?, signal?})` AsyncIterable; plugins never get `server.connected`; unknown type
  names ignored with a warning. Abort in cleanup. Full event schema `V2EventEncoded` is in `/api`.
- HOOKS (can they block/modify?):
  - `session.hook("prompt", cb)` : prompt admission; mutable draft `{prompt{text,files,agents,skills}, metadata,
    delivery}`; readonly IDs; MODIFY only (no typed reject; throwing -> preparation fails, prompt NOT admitted).
    Runs for `session.prompt` and commands that submit via it; NOT for synthetic, shell, compaction, move. Once at
    admission, retry-safe required (not exactly-once). No provider scoping.
  - `session.hook("fork")` : after history copied, before fork returns, `{sessionID}`; observe.
  - `session.hook("context"|"compaction"|"generate"|"title", cb, {providerID?})` : before model dispatch; mutable
    `system[]`, `messages[]`, `tools` (delete event.tools.write removes a tool from model view), `options`
    (maxTokens, temperature, topP, topK, penalties, seed, stop, + provider-specific keys). `compaction`/`title` accept
    `result` to skip the model call. Affects outgoing request only, not persisted history. Must register per kind.
  - `session.hook("experimental.model.resolve")` : swap `event.model` (same provider only) per request; `kind`.
  - `session.hook("model.request")` : mutate `headers` etc; `http.request` / `http.response` : native `Request`/
    `Response` (bodies one-shot streams); `kind` = primary|compaction|title|generate.
  - `session.hook("experimental.ws.handshake|send|receive")` : websocket frames, experimental.
  - `session.hook("retry")` : `{sessionID,agent,model,error{type,message,status?},attempt,decision}`; set
    `decision={retry:false}` or `{retry:true,delay:ms}`; built-in max attempts is a hard limit; context overflow handled
    separately by compaction. USEFUL for budget/attempt cap against the weak model (veto retries).
  - `permission.hook("evaluate", cb)` : after configured rules, before action or prompt; event
    `{sessionID,agent?,action,
    resources[],metadata?,source?,effect,message?}`; set `effect` to `allow|ask|deny`, `message` = denial reason or
    escalation text. Runs for allow and ask decisions ONLY; an explicit configured `deny` is final and does NOT invoke
    the hook. => the hook can DENY or ESCALATE but cannot override a config deny (good); in headless, `ask` has no human
    (use deny, or auto-reply from supervisor).
  - `shell.hook("create.before")` : `{command,cwd,timeout,shell,env}` all mutable (can rewrite command, clamp timeout,
    set env). Throwing semantics not stated for this hook (Effect page shows `event.command = "bun"` rewrite).
  - `tool.hook("execute.before")` : `{tool, input, ...}` may REPLACE input or BLOCK by throwing (Promise: `throw new
    Error("Do not read .env files")` per migrate-v1 example; Effect: `Effect.fail(new Tool.Error({message}))`, failure
    type `Tool.Error`). `tool.hook("execute.after")` : `{status:"completed"|"error", result|error}`; may replace
    `result`/metadata; cannot fail (`never`). Event field names: `event.tool`, `event.input`, `event.status`,
    `event.result`, `event.error.message`. Applies to built-in tools? Docs imply all tool executions (example guards
    `read`, `write`), but whether MCP/codemode tools and `bash` pass through it is not stated.
- Guards summary: block = throw in `tool.execute.before`, `permission evaluate` effect=deny, `ctx.tool.transform` remove
  tool, `context` hook delete tools, session permission rules deny; modify = prompt/context/model.request/shell
  create.before/execute.after; abort = `ctx.session.interrupt`; retry veto = `retry` hook. No documented "stop the
  whole session on violation" hook beyond interrupt/remove.
- Worktrees: `ctx.worktree.{create,list,refresh,remove}({projectID,...})`, config `worktree.directory`; observe
  `worktree.updated` event.
- Support V1: default export `{...Plugin.define({id,setup}), async server(){return {"tool.execute.before":...}}}`; V2
  ignores `server()`, V1 (>=1.18.29) ignores `setup()`.
- Mycelia relevance: ALL guard/evidence hooks are native plugin code, but Mycelia must write the plugin (no declarative
  deny hook). Evidence capture: `tool.execute.after` + `ctx.event.subscribe` + `ctx.storage` / write to files from
  plugin; `ctx.session.context` to dump messages; session export CLI. Plugins run INSIDE the server with host user
  authority (AGENTS.md: treat as privileged).

## Cross-cutting takeaways for Mycelia (design inputs)

1. Blocking primitives (documented): throw in `tool.hook("execute.before")`; `permission.hook("evaluate")` set
   `effect:"deny"` (cannot override config deny; only runs for allow/ask); remove tools via `tool.transform` or
   `delete event.tools.x` in `context` hook; session-scoped deny rules via `session.update({permissions})`; veto retries
   via `retry` hook; abort via `session.interrupt`. Guard-in-plugin is code, not config.
2. `opencode run --auto` = "auto-approve everything not explicitly denied": in headless runs there is no human for
   `ask`; either run with explicit deny rules + allowlist, or drive via `serve` + SDK and answer permissions with
   `permission.reply` from the supervisor (decision values documented: `once`; ACP: once/always/reject).
3. Event streams are live-only, no replay, no reconnect: the wrapper must subscribe BEFORE prompting, buffer, persist
   each event to disk, and on reconnect use `server.connected` marker + session `context` read to resync. Cross-check
   with
   `opencode session export <id> [--sanitize]` at end for durable evidence.
4. Exit codes undocumented; do not depend on them; derive verdicts from session state/export + plugin-recorded evidence.
5. Auth/env: provider key via server-process env; saved account beats env; secrets live in SQLite DB; `session export
   --sanitize` before publishing evidence; Basic auth `opencode:$OPENCODE_PASSWORD`; bind localhost.
6. Config/cli.json separation: `cli.json` is TUI-only; project guard config lives in `opencode.json(c)` + `.opencode/
   plugins/`. `opencode reload` applies config at next step boundary (guards changes mid-run apply late).
7. Weak-model controls available: `context` hook options (`maxTokens`, `temperature`), `retry` hook (cap attempts),
   `model.transform` (`enabled`, `limit.context`), `session.instructions.entry.put` (inject per-session constraints,
   evidence IDs), `experimental.generate.decisions/text` (cheap LLM judge outside session).
8. Open items to verify on target version (not in these pages): `opencode run --help` full flags and `--format json`
   event schema; exit codes; exact `permission` config syntax; HTTP route for abort/permission reply; whether MCP and
   `bash` tool calls pass through `tool.execute.before`; plugin load failure behavior (fail open vs closed).

### Answers (a)-(e)

#### (a) Go plan limits, accounting, usage endpoint, privacy/region (DeepSeek "Global")

- Plans: Go $10/mo; Go Plus $40/mo ("Higher usage limits"); Go Teams $20/member/mo (2-member min, "$5/month higher than
  Go on every model"). Paid Go models share ONE dollar-denominated monthly allowance; per-model monthly limit is a
  dollar figure shown at `https://opencode.ai/console/go#limits` and in `go.monthly_usage` of `GET
  /inference/go/v1/models` (not on the docs page). Quote: "$1.50 of usage on a model with a $15 limit uses 10% of your
  monthly allowance."
- Rolling limits: "The 5-hour limit is 20% of your monthly allowance"; "The weekly limit is 50% of your monthly
  allowance. It resets on Monday at 00:00 UTC"; monthly resets at paid-period start. Over the limit: use free models or
  **Extra Usage** (spends Console credits; off by default except Go Teams) - otherwise requests blocked.
- Per-request accounting: response `usage.opencode.allowance` ("how much the request counted toward your usage limits,
  in dollars of the plan's monthly limit"), `billing_source: go|go-plus`, `cost: 0` within limits.
- **Usage endpoint exists**: `GET https://opencode.ai/inference/go/v1/usage` with `Authorization: Bearer <Go key>` ->
  `usage.rolling|weekly|monthly {status ok|rate-limited, percent 0-100, resetsAt ISO8601}`; 401 invalid key, 403
  `EntitlementError` if not covered. Key = subscriber's personal API key or a service account key (Go/Go Plus); any
  member's personal key (Go Teams); Go Teams does not cover service accounts.
- Privacy/region: default allowed regions "Europe & United States"; "**DeepSeek V4.1 Flash and V4 Pro:** select
  **Global** under **Regions**" (Settings > Privacy, owner/admin). Retention for DeepSeek V4.1 Flash: "0 days*" with
  "DeepSeek: ZDR agreement is renewed monthly. The current agreement is valid through December 31, 2026." Default blocks
  paid endpoints that train on request data. LongCat is explicitly "Hosted in China"; the DeepSeek hosting location is
  not stated beyond needing Global. Data flowing under Global is a policy decision for Mycelia (record in the spec).
- Also: Go "designed primarily for international users"; traffic monitored for abuse; client must send stable
  `x-opencode-session` (OpenCode does).

#### (b) Jev

- Endpoint: `https://opencode.ai/inference/systemone/v1/systemone` (PAYG/Console key) and
  `https://opencode.ai/inference/go/systemone/v1/systemone` (Go key). Also OpenAI Decisions format
  `/openai/v1/decisions` (and under `/go`). Auth `Authorization: Bearer <oc_sk key>`.
- Request: `{ "model": "jev-1.14", "state": "<text>", "questions": { "<id>": { "type": "noul"|"choice"|"score",
  "instructions": "...", "criteria": ... } } }`; `choice` criteria = object option->description; `score` criteria =
  ordered array of rubric labels; multiple questions run in parallel and are answered under the same IDs. Response
  schema is not in these pages ("values and probabilities"; see <https://docs.typesafe.ai/>).
- Pricing: jev-1.14 and jev-1.13 $0.042 per 1M input tokens, output Free; jev-1.13-free Free/Free ("limited-time"; "runs
  Jev 1.13"). On Go, jev-1.14 counts against the allowance at list price (no Go discount; Go monthly limit = $10, Plus
  $40, Teams $15).
- jev-1.13-free: listed ONLY in the PAYG Console table (`opencode.ai/inference/systemone/...`), not in the Go decision
  table. Docs do not say whether the Go key works against the non-Go endpoint; Go keys are workspace API keys and the
  PAYG endpoint accepts "a personal API key or a service account key", so it likely authenticates, but the docs state
  "Free-tier chat models are only available from within OpenCode; other clients receive HTTP 403" (that sentence is
  about chat models; whether it extends to a free decision model is UNSTATED - test empirically). A Console key (not an
  anonymous call) is required either way.
- Free tier data terms: NOT documented. Only "Jev 1.13 Free is available on OpenCode for a limited time." It is not
  among the privacy exceptions (US/EU, zero-retention, no training) but no TypeSafe-specific retention/training claim
  exists; Jev is absent from the Go privacy table. Treat as unknown; get terms from TypeSafe AI.

#### (c) Auth header form and plugin/script use of OpenCode's stored credential

- Header: `Authorization: Bearer oc_sk_...` for all Console API and inference endpoints (inference also accepts
  `x-api-key`; providers API also `api-key`/`x-goog-api-key`). Keys are per-workspace; personal (acts as member) or
  service-account; Restricted scopes available (Models Request, Usage Read).
- Stored credential: NOTHING in these pages documents a way for a plugin/script to borrow OpenCode's stored provider
  credential. Documented routes are: put the key in an env var / file and reference it from config (`{env:}` / `{file:}`
  accepted for provider values such as `apiKey` and `settings.tls`, v2.3.0 notes), or read the plugin's own
  `ctx.options`. Relevant hints: legacy `auth.json` is imported into the new credential store (v2.2.7),
  `credential.updated` event exists (no secret in payload), and v2.3.1 notes embedded SDK with in-memory DB no longer
  imports `auth.json`. A plugin's `ctx.client` talks to the OpenCode server (RPC, data, usage), not to provider
  endpoints with the key. For Go allowance specifically, the server exposes `usage.limits` /
  `data.location.usage.limits` (Console budgets and Go plan allowance) so a plugin can read allowance without the raw
  key (endpoint details are in `packages/protocol/openapi.json`). For direct Jev calls, provision a separate Console
  service-account key (Restricted: Models Request) via env/secret manager; do not read the auth store.

#### (d) Budgets / usage-export as cost guard

- Budgets: workspace, per-member, per-service-account, tag, per-model scopes; monthly USD; reset 1st 00:00 UTC; breach
  -> HTTP 429 `Policy budget exceeded`; checked at request start (slight overshoot). Does NOT count Go in-plan usage or
  free models; DOES count paid Console models, priced BYOK models, web search ($0.01), and Go extra usage paid from
  credits. So budgets guard Jev PAYG spend/Go-extra spend, not the Go allowance. Setting Extra Usage off plus a
  `$0`/small budget on the factory service account is a hard stop for paid spend.
- Go allowance guard: poll `GET /inference/go/v1/usage` (percent/status/resetsAt) and per-request `opencode.allowance`.
- Usage export: `GET /console/api/v2/usage/export?range=7d|30d|90d[&user_id=svcacct_...]` CSV (per UTC day x service
  account x provider x model; requests, tokens incl cache, `cost_usd`), needs Usage Read key (service account key or
  owner/admin personal key), 300 req/min shared, lag ~1 min, 90-day cap, excludes web search; free-model requests
  included at zero cost. Suitable for daily reconciliation/audit evidence per run; use `user_id` to isolate the factory
  service account. No documented budgets-management REST endpoint (only a **Budgets Read/Write** key permission and
  Console UI/MCP).
